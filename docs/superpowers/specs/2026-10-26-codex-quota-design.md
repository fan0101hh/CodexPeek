# CodexPeek 第一版设计

日期：2026-10-26。状态：用户已确认继续实施。

## 产品范围

在当前项目目录开发原生 macOS 应用，项目名称为 CodexPeek，计划公开发布到 GitHub；不添加 LICENSE，不称为开源项目。额度监控为第一版，后续可扩展其他信息展示。应用管理多个 Codex 订阅账号，悬浮窗最多同时展示两个账号。以约 200 × 64 pt 的横向胶囊作为初始布局目标，实际尺寸随系统字体及辅助功能需求调整。每行显示账号别名、5 小时剩余百分比、周剩余百分比，标记本机当前使用的账号。点击展开详情和账号选择；悬停显示重置时间及数据更新时间。支持拖动、记忆位置、置顶和菜单栏入口。

两个展示位置默认配置为当前账号及一个固定账号；用户可改为两个固定账号。当前账号与固定账号重复时只展示一次。账号不存在、退出登录或切换中时清楚显示状态，不使用其他账号的数据补位。

## 技术选择与项目结构

采用 Swift、SwiftUI 和 AppKit，不引入 Electron、WebView 或为界面额外运行的服务。使用 Swift Package Manager 分离原生应用和可测试核心库；用脚本将编译产物与资源打包为 .app。开发初期不引入项目生成器或复杂多包结构。

## 账号与数据流

流程为账号发现 → 用户选择展示账号 → 独立认证上下文查询 → 标准化额度快照 → 主线程更新界面。每个快照携带稳定账号标识、读取时间、额度窗口和数据状态；账号标识不使用邮箱作为唯一依据。

已验证原生 HTTPS 可独立查询有效账号的用量。第一版使用 Codex 内部只读用量端点，避免依赖内部专用的 App Server 外部令牌登录及常驻子进程。只读取主订阅 rate_limit；按 limit_window_seconds 识别 18,000 秒和 604,800 秒窗口，使用 used_percent 与 reset_at；忽略代码审查和额外额度桶，缺失窗口显示不可用。接口兼容性风险封装于 UsageClient。

不为 cc-switch、Magpie 分别实现切换工具适配器；当前账号以 Codex 自身认证状态为准。本机已检查 ~/.cc-switch/codex-login-stash.json 的结构，其中 logins 保存两个账号的授权记录，含 access_token、account_id、id_token、refresh_token；codex-login-history.json 只保存指纹和时间历史，不作为认证来源。首版可将 stash 作为只读账号来源，提供可配置路径，监听文件变化后重新读取。该格式属于工具内部格式，解析失败需显示明确状态。仅验证了结构，尚未验证凭据有效性及独立额度查询。

接入阶段先验证每个账号的独立查询上下文。查询不得通过覆盖 ~/.codex/auth.json 或切换本机账号实现。不主动刷新共享来源中的 refresh_token，也不写回源文件，以免与原工具的令牌轮换冲突；访问令牌过期时先重新读取来源，仍无有效授权则提示用户在原工具重新登录。需要常驻子进程时，必须确认不会在后台自行刷新共享令牌；每个账号的进程生命周期必须有界、可复用且可在移除账号或退出时清理。

已确认来源中的过期令牌不能用于查询；第一版提示在原工具重新登录，不实现新授权流程或独立 Keychain 存储。当前有效账号查询验证成功，不代表所有保存的账号都有效。

## 刷新与异常处理

默认对两个可见账号每 5 秒查询一次；未展示账号不查询。HTTP Provider 不提供更新通知。相同账号同一时刻最多一个请求；超时、限流、断网使用有上限的退避，恢复后回到正常间隔。系统休眠暂停，唤醒后刷新。每秒检查两个明确路径的文件修改时间、大小和 inode，变化后重读；异常额外重试一次，处理原子替换；变化事件触发重新识别账号，但不单凭文件变化推断身份。

账号切换或凭据变化时使旧请求失效，避免迟到响应覆盖新状态。认证失败、读取失败、数据过期分别显示；缓存必须标注更新时间。5 秒表示客户端目标查询周期，不保证服务端数据更新周期。到达重置时间后重新查询，不能自行假设额度已恢复。

## 凭据与公开仓库

仓库仅包含代码、资源、文档及人工构造的测试数据。账号认证、工具数据库、真实响应、邮箱、日志及本机绝对路径均不得作为示例提交。应用不记录令牌、认证头和原始认证响应。访问令牌仅在内存中，快照不落盘；普通设置及账号别名、标识和窗口位置保存在 UserDefaults；现有工具凭据只读、不修改源文件。

接入工具优先通过明确路径及格式读取，不扫描整个用户目录。公开文档解释读取范围、存储位置及撤销方法。第三方工具相关能力按实际验证版本说明兼容性。

## 验证与发布

核心测试覆盖不同额度桶及缺失字段、账号去重、切换竞态、过期快照、退避与查询合并。使用零依赖可执行检查器运行人工数据测试（本机 CLT 不含 XCTest），不在 CI 登录真实账号或查询真实额度。窗口交互、跨桌面行为、休眠恢复及两款切换工具需要 macOS 本机验证。

CI 在 macOS 上编译和运行核心测试。脚本先支持本地生成未签名 .app；面向用户的正式下载需要另外配置 Developer ID 签名、公证及 GitHub Release。首版分别验证 Apple Silicon 和 Intel 构建，不提前声称已支持通用二进制。

轻量化是实现目标；完成真实双账号查询后测量整个进程树的内存、空闲及轮询 CPU、查询耗时和请求频率。不能只测界面进程，也不提前承诺固定内存或耗电数值。

## 实现顺序

先验证账号识别和两个账号并行只读查询，再实现核心模型及调度、胶囊界面、打包和公开仓库文档。若认证验证不成立，应先调整接入方案再实现界面与发布流程。
